## Context

Currently, the Monster Hunter Wilds Build Crafter fetches massive JSON files from the `public/data` directory. The data is generated by Python scripts (`weapons.py`, `fetch.py`) that fetch from an external API. This setup is difficult to scale and lacks queryability during the development and data-curation phase.

## Goals / Non-Goals

**Goals:**
- Centralize all game data into a single `mh_wilds.db` SQLite file.
- Normalize the data structure to avoid redundancy (e.g., skill descriptions stored once).
- Enable complex filtering and validation of data before it reaches the frontend.
- Maintain compatibility with the current React frontend by providing an export-to-JSON utility.

**Non-Goals:**
- Replacing the React frontend's state management with direct SQL queries (WASM) in this phase.
- Implementing a full web-based backend API (FastAPI/Express) for the production site.
- Real-time synchronization with the external API (staying with periodic manual fetches).

## Decisions

- **SQLite for Local Storage**: Chosen for its zero-configuration setup and compatibility with Python.
- **Normalization Strategy**: 
    - `weapons`: Main weapon stats.
    - `armor`: Main armor stats.
    - `skills`: Descriptions and rank info.
    - `armor_sets`: Mapping pieces to bonuses.
    - `decorations`: Deco-specific info.
- **Python Data Pipeline**: Update `weapons.py` to use a `DatabaseManager` class that abstracts the SQL complexity.
- **Incremental Loading**: Use `INSERT OR REPLACE` to handle data updates without duplicating records.

## Risks / Trade-offs

- **Synchronization**: There is a risk of the DB and JSON files getting out of sync if the export step is skipped. We will mitigate this by combining ingestion and export into a single workflow script.
- **Complexity**: Normalizing data adds overhead to the ingestion scripts, but significantly reduces errors in skill/set-bonus data.
